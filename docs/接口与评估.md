# Guardian｜接口与评估约定

## 事件输入

```js
guardian.process(text, {
  role: 'caller',        // caller 或 user，不能靠内容猜说话人
  seconds: 48,           // 非负且单调，脚本时间不能伪装成真实时间
  source: 'manual',
  features: null        // 可选外部模型向量，只提供特征
});
```

单句 1–500 字。当前语音来源、身份和执行动作均不可观测。老人自述“已经转账”只标记为自述已执行，不计入事前提醒；还需区分被诱导、尝试操作和实际发生损失。

## 特征向量

`authority, fear, urgency, isolation, reward, install_app, screen_share, otp_request, money_transfer, password, qr, remote_control`。

每项是有限数值，范围 0–1。`authority` 表示自称身份，不能当作身份认证。输入必须解释否定、引用、教育语境和说话人角色。模型失败时保留明确的失败/降级状态；不能把无法分析标成“安全”。

模型的系统提示与协议见 `providers/llm_extractor.mjs`。提示把对话作为不可信数据。JSON 通过数值校验，但校验不能证明语义正确，也不能消除所有提示注入风险。后续应将攻击样本纳入测试，并避免让模型执行外部动作。

## 输出与审计

每轮保留文本、说话人、来源、信号与证据、图快照、风险构成、策略级别、具体动作、候选权重与首选预测是否命中。网页可导出 JSON。本地规则可复算；外部模型未返回证据片段时不伪造引文。

`policy.speak` 是播报决策，不代表音频已被老人听见。浏览器 TTS 可能不可用。`familyEvent.status=confirmed` 只代表本页模拟点击；不代表真实家属已收到消息。

## 指标定义

- **动作级 BHAR**：有目标危险动作的场景中，在实际执行时刻之前，至少一次出现与该动作相符的主动提醒（level ≥3）的场景占比。必须严格早于执行，不能使用仅有风险分、无动作提醒的轮次。
- **主动误扰率**：正常场景中出现至少一次主动提醒的比例；边界场景单列。屏幕轻提醒另应测量提醒负担，不因未达到主动阈值就视作完全无打扰。
- **提前时间**：执行时刻减首次相关主动提醒时刻；只在命中场景计算均值，必须同时报告未命中数量，避免只看成功样本。
- **下一动作 Top-1**：具有后续动作标签的时点中，首选与下一个实际请求相符的比例。下一动作权重若无校准，不得称为发生概率。
- **延迟**：语音片段结束到提醒开始的真实 p50 / p95，含 STT、模型、网络和 TTS；本地核心运算耗时不能代替端到端时延。

## 当前实验

50 个合成开发脚本：20 scam、20 normal、10 boundary。两种方法使用同一对话序列；关键词基线遇到预定义可疑词就提醒，不处理否定；Guardian 使用序列政策。LLM 基线未运行。

危险请求统一位于 48s，执行假定为 56s。平均提前 8s 是脚本设定，不是实测效果。所有参数与脚本都公开，报告保留漏检，不能把开发集成绩冒充盲测结果。

## 后续评估设计

1. 经同意获得匿名真实样本，至少两名标注者独立标注说话人、危险请求、最迟安全提醒点和执行事件；保留分歧并仲裁。
2. 按来源和完整对话划分训练/开发/测试，防止同一模板改写跨集合泄漏；锁定测试集后才选阈值。
3. 对比关键词、单轮 LLM、LLM＋无序信号、LLM＋有序图；增加去掉 spike、去掉提醒保留的消融。
4. 在固定主动误扰预算下比较 BHAR，并报告样本数、置信区间、方言/STT 错误分层结果。
5. 单独招募用户测试可读性、理解时间、暂停意愿、语音可接受度和自主权感受。模型指标不能代替用户效果。

## 数据与可行性

默认不录音、不持久存储、不创建联系人。真实试点需要同意、退出、摘要最小化、访问控制与删除机制。技术原型不构成已经完成合规或终端权限评审的证明。先选择合法可接入的实验通话环境，再扩展到真实终端。
