# Guardian｜演示与答辩

## 3 分钟路演逐字稿

**0:00–0:25｜问题**

“如果一个老人已经相信电话里的客服，再多一条‘注意诈骗’可能也不够具体。我们想解决的是：对方正在让老人做什么，系统应该在哪个动作前开口。Guardian 是一条数字安全带，目标是争取一次暂停和独立核实的机会。”

**0:25–0:45｜定位**

“国家反诈中心与国家反诈 AI 已经提供重要的预警、核验和研判能力。我们的范围是连续对话中的动作与介入时机。我们没有做同条件的竞品实验，因此不宣称效果领先。”

**0:45–1:40｜现场演示**

“现在，对方说自己是客服。系统记录身份线索，但不打断。接着制造扣费担忧，再催促立即处理。注意，风险上升与立刻打断是两件事。

当对方让老人下载会议软件，老人端出现轻提醒，后台把共享屏幕列为下一步的首选候选。这个 61% 是图谱权重，不是训练得到的概率。

下一句真的要求打开共享屏幕。系统风险升到 95，主动说：请不要共享屏幕。提醒针对动作。老人可以自己选择请家人确认。

这里是本页模拟的家属视图：显示发生了什么、需要确认什么。我们不知道老人是否真的操作，所以不会写‘已成功拦截’。”

**1:40–2:10｜技术**

“中间有四层：信号提取、演化图、动态风险、介入政策。模型只提取特征，不能直接决定处置。网页用同一份核心算法实时计算；在线模型接口也已实现，但本次演示默认规则模式，不依赖网络。高危动作有即时风险下限，提醒会保留到本人确认，同类提醒避免反复打扰。”

**2:10–2:40｜证据与不足**

“我们公开了 50 条合成开发脚本。规则原型在 20 个危险场景中有 15 个在脚本假定执行前给出相关动作提醒，正常 20 条与边界 10 条未主动误扰。另 5 条隐晦表达漏掉了，比如‘把短信里的六个数念一下’。这说明规则覆盖不够，也正是语义模型下一步要接受的检验。这不是泛化性能，脚本里的提前 8 秒也是人为设定，不能称为真实防损效果。”

**2:40–3:00｜下一步**

“下一步我们会接入真实语音与操作时间戳，在独立标注的对话上比较基线，并测试老人是否能理解、接受并执行提醒。我们最终想证明的是：用更少的打扰，在关键动作前多争取一次停下来的机会。”

## 1 分钟操作流程

| 时刻 | 操作 | 应出现 |
|---|---|---|
| 0s | 选客服场景，重置 | 风险 0，等待对话 |
| 5s | 下一句 | 风险 10，静默 |
| 12s | 下一句 | 风险 24，静默 |
| 20s | 下一句 | 风险 35，静默 |
| 28s | 下一句 | 风险 45，安装提醒，共享候选 61% |
| 38s | 下一句 | 风险 95，具体共享提醒 |
| 48s | 请家人帮我确认 | 证据摘要，操作情况未知 |
| 55s | 模拟我已陪同核实 | 本页确认闭环 |

用手动「下一句」能跟上讲解节奏；「播放演示」每 12 秒输入一句，五句到 48 秒结束，再留时间演示家属。需要语音时提前勾选并彩排中文声音；没有声音就直接读出屏幕提醒。

不要演示真实账号、验证码、转账或真实联系人。现场使用项目里的虚构台词即可。

## 8 页演示文稿提纲

1. **Guardian 银盾陪护**：一句话、主视觉、具体危险动作。
2. **用户卡在什么时刻**：信任 → 催促 → 操作；区分内容识别和动作介入问题。
3. **互补定位**：官方公开能力、自己的有限范围，不做未经验证的排他比较。
4. **一段对话的变化**：五句台词、实时风险与提醒等级。
5. **四层架构**：特征接口可替换，图、风险、政策可复算。
6. **干预为什么发生在这里**：关键动作下限、克制提醒、去重和本人确认。
7. **测试与失败案例**：实际合成结果、5 个漏检、没有真实效果或 LLM 基线成绩。
8. **下一步与团队**：STT、独立标注集、可用性验证、权限可行性、分工。

## 常见答辩问题

**这是不是几个 API 拼接？**

“API 负责输入与特征映射，风险状态和动作策略由独立模块计算。现场可替换特征层而保留同一套决策。我们的贡献目前是可验证的系统与策略设计，不声称发明了新的基础模型。”

**为什么不用国家反诈中心？**

“应该继续使用。Guardian 不替代官方能力，也不掌握涉诈账号库。我们只验证连续对话里的动作提醒与家属确认这一有限体验。”

**能听到真实手机来电吗？**

“当前不能。这是浏览器原型，输入来自脚本或文本。真实接入需要先在目标通话环境验证权限和音频来源，不能承诺普通网页后台监听。”

**演示里的 95 与 61% 从哪里来？**

“95 是公开公式和规则计算的风险分，61% 是预设图谱候选权重；都未经概率校准。我们显式区分启发式分数与测得概率。”

**75% BHAR 是不是说明有效？**

“只能说明这些开发脚本中的行为。它们不是独立样本，执行时间也是假设。关键词基线在这个集合上 BHAR 同为 75%，我们的正常和边界主动误扰更少，但不能据此推断真实场景领先。”

**模型真的接上了吗？**

“实现了可配置 HTTPS 模型适配器、本地代理、特征校验和降级路径，接口用模拟响应测试过。没有配置真实密钥，因此没有供应商联调与模型成绩；托管演示默认是规则模式。”

**能阻止转账吗？**

“现在只能提醒，不能控制银行应用。我们把‘提醒发出’、‘用户确认’和‘真实操作停止’当作不同事件。没有操作遥测就不声称成功阻止。”

**一直误报怎么办？**

“把正常场景误扰、老人接受率与 BHAR 一起优化。高风险只提醒具体动作，普通身份声明不播报。当前规则仍可能在复杂否定、正常远程协助等场景误判，要在独立数据中暴露它。”
